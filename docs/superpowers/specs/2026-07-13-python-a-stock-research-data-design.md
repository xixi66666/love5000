# python-a 单股深度研究数据设计

## 1. 背景

`website/python-a` 当前围绕少量自选股提供实时行情、技术结构、AI 多维分析、交易复盘和 Obsidian 长期记忆。现有研究页已经形成左侧自选股、中间行情与技术分析、右侧复盘与 AI 的三栏工作台，但单股研究数据主要集中在行情、均线和换手率，缺少估值、资金筹码、研报和公告等上下文。

本设计参考已安装的 `a-stock-data` V3.4.0 Skill，从中选择适合当前应用的数据端点和降级策略。Skill 继续作为开发期数据接口参考；运行时只引入经过适配、测试和安全检查的 Provider，不直接执行整份 `SKILL.md`。

## 2. 目标

首期建设单股深度研究能力：

- 在现有研究页中展示估值、市值、行业概念、资金流、融资融券、股东户数、未来解禁、研报和公告。
- 保留现有行情、技术结构、AI 分析和复盘流程，不改变 `/api/stock`、`/api/watchlist` 的既有行为。
- 采用分区懒加载，降低首屏延迟和第三方接口限流风险。
- 主数据源失败时自动切换可用备用源，并始终展示实际成功来源和数据时间。
- 将研究数据的精简快照提供给 DeepSeek、SpringAI Agent 和 Obsidian 复盘记录。
- 保持 Python 3.9+ 兼容，首期不引入 `mootdx`、`pandas`、`stockstats`。

## 3. 非目标

- 不一次接入 `a-stock-data` 的全部 43 个端点。
- 不在首期建设全市场涨停情绪、行业轮动、ETF 期权或市场热榜页面。
- 不替换现有东方财富前复权日 K 和历史换手率计算。
- 不把 Skill 中统一 30 倍 PE、PEG 阈值等观点性估值规则作为系统事实。
- 不在浏览器中直接请求第三方数据源。
- 不关闭 TLS 证书校验，不使用未经保护的跨线程共享 Session。

## 4. 总体架构

新增 `StockResearchService`，以页面分区为业务边界编排 Provider、缓存、降级和 AI 快照：

```text
StockResearchService
├── overview
│   ├── 腾讯：实时行情、PE、PB、总市值、流通市值
│   ├── 东方财富：行情和估值备用源
│   └── StockMetadataService：行业、概念和本地降级
├── capital
│   ├── 资金流
│   ├── 融资融券
│   ├── 股东户数变化
│   └── 未来 90 天解禁
└── events
    ├── 个股研报
    └── 公司公告
```

建议新增文件：

```text
website/python-a/services/
├── stock_research_service.py
├── research_provider.py
├── tencent_quote_provider.py
├── eastmoney_research_provider.py
├── sina_fund_flow_provider.py
└── cninfo_announcement_provider.py
```

职责如下：

- `research_provider.py`：定义 Provider 返回模型、数据源元信息和公共异常。
- 各 Provider：负责单一数据源的请求、解析、单位归一化、超时和异常转换。
- `StockResearchService`：负责分区编排、缓存、主备切换、局部失败和精简快照。
- `server.py`：只负责路由、六位股票代码校验、`force=1` 解析和 JSON 响应。

## 5. HTTP API

新增接口：

```text
GET /api/stocks/{code}/research/overview
GET /api/stocks/{code}/research/capital
GET /api/stocks/{code}/research/events
```

三个接口都支持可选查询参数：

```text
force=1  绕过当前分区缓存并刷新
```

`events` 接口额外支持：

```text
kind=all|reports|announcements  默认 all
page=1                          从 1 开始
page_size=10                    默认 10，最大 20
```

首次打开“研报公告”使用 `kind=all&page=1&page_size=10`。点击某一栏的“加载更多”时，只请求对应 `kind` 的下一页，另一栏的列表和分页状态保持不变。

一个分区可能由多个来源组成，因此来源信息放在每个数据块中，而不是使用单一顶层 `provider`：

```json
{
  "success": true,
  "section": "capital",
  "code": "002580",
  "blocks": {
    "fund_flow": {
      "success": true,
      "provider": "sina",
      "fallback_used": true,
      "data_date": "2026-07-11",
      "fetched_at": "2026-07-13T14:30:00+08:00",
      "data": {}
    },
    "margin": {
      "success": true,
      "provider": "eastmoney",
      "fallback_used": false,
      "data_date": "2026-07-11",
      "fetched_at": "2026-07-13T14:30:01+08:00",
      "data": {}
    }
  }
}
```

数据块失败不导致整个分区失败：

```json
{
  "success": false,
  "message": "融资融券数据暂不可用",
  "provider": null,
  "retryable": true
}
```

接口顶层 `success=false` 只用于非法股票代码、未知分区或服务无法构造任何有效响应等整体错误。

## 6. 数据内容与来源

### 6.1 概览

展示字段：

- PE(TTM)
- PB
- 总市值
- 流通市值
- 量比
- 振幅
- 涨停价
- 跌停价
- 所属行业
- 概念标签

降级链路：

```text
实时行情和估值：腾讯 → 东方财富
行业和概念：东方财富 F10 → Tushare → 本地自选股档案
```

金额和比例在 Provider 层统一为明确单位，前端只负责格式化显示。响应字段需要在名称或元数据中标明元、万元、亿元、股、百分比等口径。

### 6.2 资金筹码

资金流展示：

- 当日主力净流入
- 近 5 日方向
- 近 20 日方向
- 最新数据日期

融资融券展示：

- 最新融资余额
- 融资余额近期变化
- 最新交易日

股东户数展示：

- 最新股东户数
- 环比变化
- 报告期

解禁预警展示：

- 未来 90 天解禁日期
- 解禁数量
- 实际可流通数量
- 可计算时展示占流通股比例

降级链路：

```text
资金流：东方财富 → 新浪
融资融券：东方财富 → 暂不可用
股东户数：东方财富 → 暂不可用
解禁数据：东方财富 → 暂不可用
```

没有可靠备用源时不伪造降级来源，也不混用不同含义的替代指标。

### 6.3 研报公告

研报默认展示最新 10 条：

- 标题
- 发布机构
- 评级
- 发布日期
- 可用时展示预测 EPS
- 原文或 PDF 链接

公告默认展示最新 10 条：

- 标题
- 发布日期
- 公告类型
- PDF 或原文链接

降级链路：

```text
研报：东方财富 → 暂不可用
公告：巨潮 → 深交所官方（深市）或东方财富（沪市）
```

“加载更多”按数据类型独立翻页，不在首次请求中拉取全部历史记录。

## 7. 页面设计

现有顶部行情和“技术结构 / AI 盘后观察”保持不变。在技术分析下方、长期记忆区域上方新增：

```text
[ 概览 ] [ 资金筹码 ] [ 研报公告 ]
```

### 7.1 概览标签

第一行使用紧凑指标布局展示 PE、PB、总市值、流通市值、量比和振幅。第二行展示行业、概念标签、涨停价和跌停价。数据块底部显示真实来源和数据时间。

### 7.2 资金筹码标签

使用四个无嵌套的数据区展示资金流、融资融券、股东户数和解禁预警。每个数据区独立显示来源、数据日期、加载状态和错误状态，因此同一页面允许出现多个来源。

### 7.3 研报公告标签

桌面端左右两栏，移动端上下排列。研报和公告分别支持加载更多。长标题允许换行，不得挤压日期和来源信息。

### 7.4 交互状态

- 概览随选股自动加载。
- 资金筹码和研报公告在首次打开标签时加载。
- 已加载标签切换时直接使用缓存。
- 用户点击现有顶部“刷新数据”按钮时，先保持原行为刷新自选股行情，再使用 `force=1` 刷新当前研究标签；尚未打开过的懒加载标签不提前刷新。
- 加载过程使用固定高度骨架，避免布局跳动。
- 单项没有记录时显示“暂无数据”。
- 主备源都失败时只影响对应数据区。
- 数据源切换不弹阻塞提示，但数据块必须立即显示实际成功来源。
- 外部链接在新标签页打开，并设置 `noopener noreferrer`。

## 8. 缓存、限流与降级

内存缓存：

```text
overview：180 秒
capital：30 分钟
events：30 分钟
```

缓存键包含股票代码、分区和数据块，防止不同来源的结果互相覆盖。首期不将运行时缓存写入 Obsidian 数据目录。

东方财富请求经过带 `threading.Lock` 的统一限流器。网络错误、`429` 和 `5xx` 允许有限重试；`403` 不连续重试，立即进入备用源。共享 HTTP 客户端必须明确处理线程安全，不能直接复制 Skill 中无锁的全局 Session 和时间戳实现。

Provider 切换成功后返回备用源名称、数据时间以及 `fallback_used=true`。主备源都失败时返回结构化局部错误，不将旧来源名称附在失败数据上。

## 9. AI 与 Obsidian

点击 AI 维度分析或专业报告时：

```text
读取当前研究缓存
→ 对缺失分区按需补取
→ 生成精简 research_snapshot
→ 提交给 DeepSeek 或 SpringAI Agent
→ AI 响应同时返回本次实际使用的 research_snapshot
```

前端把 AI 响应中的快照保存在当前页面状态中。保存复盘时提交这份快照，从而保证 Obsidian 记录的数据与生成 AI 结论时的数据完全一致。AI 生成后即使用户手动刷新页面数据，也不替换已生成结论关联的快照；再次生成 AI 分析时才产生新快照。如果用户未生成 AI 就直接保存复盘，后端使用保存时的研究缓存构造快照。

精简快照包含：

- 核心估值和市值
- 行业与主要概念
- 资金筹码摘要
- 最新研报和公告标题摘要
- 每个数据块的实际来源和数据日期
- 局部不可用信息

保存复盘时将同一口径的精简快照写入 Obsidian，保留数据事实、来源、时间和模型分析之间的明确边界。不写入几十条完整原始响应，避免提示词 Token 和笔记体积失控。

AI 提示词继续要求：

- 不编造未提供的公告、新闻或财务数据。
- 不输出确定性买卖指令。
- 明确数据时点和缺失项。
- 保留研究辅助、风险提示和非投资建议边界。

## 10. 安全与数据质量

- 股票代码只接受六位数字，并在进入 Provider 前校验。
- 第三方标题、机构名称和概念标签按不可信文本处理，前端统一转义。
- 外部链接只允许 `https` 和配置的可信域名。
- 不把 API Key、Cookie、Authorization 或第三方原始响应写入日志。
- 不关闭 TLS 证书校验。
- 每个响应记录实际来源、抓取时间和数据日期。
- 不用 `0` 代替缺失估值；缺失字段使用 `null`。
- 前复权、不复权以及财务报告期等口径必须显式记录。
- Apache-2.0 来源代码保留必要的版权和许可证说明；上游数据接口仍按各数据源规则使用。

## 11. 测试策略

后端自动测试至少覆盖：

- 腾讯行情字段解析、股票市场映射和单位转换。
- 主源成功。
- 主源失败后备用源成功，并返回实际备用源名称。
- 主备源同时失败时的局部错误。
- 同一分区不同数据块来自不同来源。
- 缓存命中以及 `force=1` 绕过缓存。
- 东方财富并发限流。
- AI 精简快照字段、来源信息和长度边界。
- 非法六位代码和未知路径。
- 第三方标题转义及不安全链接拦截。

测试使用 Fake Provider 或可注入 HTTP 客户端，不访问真实外部行情、研报、公告、DeepSeek 或 SpringAI 服务。

页面验证至少覆盖：

- 桌面与移动端三个标签的布局。
- 加载、空数据、部分失败和备用源状态。
- 长标题和多个概念标签不溢出。
- 标签切换不产生重复请求。
- 当前标签刷新只绕过对应缓存。
- AI 分析与 Obsidian 保存包含精简研究快照。
- 浏览器自动化截图中不存在重叠、截断或异常布局跳动。

## 13. 验收标准

- 选择自选股后，概览标签自动展示估值和行业概念。
- 首次打开资金筹码或研报公告时才发起对应请求。
- 主源失败且备用源成功时，页面展示备用源名称和实际数据时间。
- 一个数据块失败不会影响基础行情、其他数据块和右侧复盘表单。
- AI 分析和专业报告包含精简研究数据，同时标注来源和时点。
- Obsidian 每股复盘保存精简研究快照，不保存第三方完整响应。
- 现有 `/api/stock`、`/api/watchlist`、交易复盘和长期记忆功能不回归。
- Python 3.9+ 环境可以运行，不要求安装 `mootdx`、`pandas` 或 `stockstats`。
- 后端自动测试通过，桌面与移动端浏览器验证通过。
