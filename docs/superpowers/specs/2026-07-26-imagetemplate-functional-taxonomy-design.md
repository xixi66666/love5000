# Imagetemplate 两级功能分类设计

## 背景

`imagetemplate` 当前聚合 47 条精选图片模板与 4409 条 Prompt Console 模板，共 4456 条。主页把 7 个来源作为最显眼的筛选维度，同时直接展示 95 个公开库原始分类和 8 个精选分类。原始分类中包含“文本”“精选”“STRUCTURED”等非功能标签，用户难以按实际任务找到模板。

本次改造将模板库的核心导航从“来源”调整为“一级功能 + 二级场景”。来源仍被保留，但移入默认收起的高级筛选。

## 目标

- 全部 4456 条模板都获得稳定的一级功能和二级场景。
- 主页默认使用两级功能树导航模板。
- “编程与技术开发”作为明确、可见的一级功能。
- 分类结果可重复、可测试，不依赖运行时 AI 调用。
- 保留来源、原始分类以及现有查询参数，避免破坏已有接口调用。
- 新增模板时可通过集中规则自动分类，并允许少量人工覆盖。

## 非目标

- 不修改共享 Prompt Console 数据源的原始分类。
- 不使用 OpenAI 或其他模型在线或批量生成分类。
- 不让一条模板同时属于多个主分类。
- 不删除来源信息或现有来源筛选能力。
- 不重做 Prompt 渲染、图片生成和四场景主页结构。

## 功能分类树

## 分类架构

新增独立的 `TemplateFunctionClassifier`，负责把模板已有的标题、原始分类和标签转换为功能分类结果。Controller、分页服务和前端不包含关键词判断。

分类器依赖三个只读组成部分：

1. 分类目录：声明一级功能、二级场景、显示顺序和稳定 slug。
2. 人工覆盖表：处理精选模板和少量无法通过通用规则准确识别的模板。
3. 有序匹配规则：声明目标场景、匹配字段和关键词。

分类结果包含：

- `functionCategory`
- `functionCategorySlug`
- `functionScene`
- `functionSceneSlug`

原有 `category`、`categorySlug`、`sourceId` 和 `sourceName` 保持不变。

## 分类优先级

分类按以下顺序执行，命中后立即停止：

1. 模板 ID 人工覆盖。
2. 标题高置信度规则。
3. 原始分类与标签组合规则。
4. 标题普通关键词规则。
5. 来源的低优先级默认规则。
6. “其他工具 / 通用提示词”兜底。

不扫描完整 `promptTemplate`。长 Prompt 往往包含大量角色、输出格式和例子，扫描全文容易因偶然关键词误分类。

“编程与技术开发”规则必须显式覆盖 Python、Java、JavaScript、TypeScript、SQL、React、Vue、Spring、FastAPI、代码、编程、开发、调试、测试、API、数据库、架构、DevOps、云原生、网络安全等关键词，并通过更具体规则把它们分配到对应二级场景。

所有规则都必须是确定性的。同一输入在不同启动、机器和构建中得到相同结果。

## 聚合与查询数据流

1. 现有加载器读取 47 条精选模板和 4409 条公开库模板。
2. 适配器保留原始分类和来源信息。
3. 聚合服务在启动时逐条调用功能分类器，写入四个功能分类字段。
4. 聚合服务构建模板 ID 索引、功能树计数、来源计数和现有分类计数。
5. 列表查询先按一级功能和二级场景筛选，再叠加关键词、来源、原始分类和图片相关筛选。
6. 分页只返回摘要；详情继续按 ID 返回完整模板。

分类在聚合阶段计算一次。每次 HTTP 分页请求不得重新执行 4456 条分类。

## API 设计

`GET /api/image-templates` 新增可选参数：

```text
functionCategory
functionScene
```

二级场景必须与所选一级功能匹配。只传二级场景时允许跨一级搜索同名场景；同时传入时使用精确组合筛选。

列表摘要和详情模板新增四个功能分类字段。原有 `source`、`category`、`imageOnly`、`keyword`、`page` 和 `size` 参数继续有效。

`GET /api/image-templates/meta` 新增 `functionCategories`，结构为：

```json
[
  {
    "name": "编程与技术开发",
    "slug": "programming-development",
    "count": 300,
    "scenes": [
      {
        "name": "代码生成",
        "slug": "code-generation",
        "count": 80
      }
    ]
  }
]
```

一级分类的 `count` 等于其二级场景数量之和；全部一级分类的数量之和等于当前实际模板总数。

`GET /api/image-templates/categories` 和 `/meta` 中原有分类、来源字段继续保留。

## 前端交互

灵感大厅筛选区调整为：

1. 一级功能分类横向导航，首项为“全部功能”。
2. 选中一级功能后展示对应二级场景导航，首项为“全部场景”。
3. 关键词输入和“仅图片相关”保留。
4. 来源与原始分类放入默认收起的“高级筛选”。

切换一级分类时自动清除已经不适用的二级场景。切换二级场景、来源或关键词继续复用当前的重置分页流程。

模板卡片和详情的主标签显示“一级功能 · 二级场景”；来源显示为次要信息。无结果状态的“清除筛选”需要同时重置一级功能、二级场景、来源、原始分类、图片开关和关键词。

移动端允许一级和二级导航在各自容器内横向滚动，但页面本身不能出现横向溢出。

## 错误与降级

- 功能分类器不得因单条模板缺少标题、分类或标签而阻止应用启动。
- 空字段按未命中处理，最终进入兜底分类。
- 功能目录中不存在的规则目标在测试阶段视为配置错误。
- 聚合库处于现有 `DEGRADED` 状态时，只对实际成功加载的模板生成分类和计数。
- 非法分页参数继续返回现有稳定 400 响应。
- 不存在的功能 slug 返回空分页结果，不暴露内部规则。

## 测试与验收

### 单元与接口测试

- 15 个一级功能及其二级场景具有唯一、稳定 slug。
- 分类器覆盖人工覆盖、标题优先、分类标签组合、来源低优先级和兜底路径。
- Python、Java、调试、前端、后端、数据库、DevOps、安全等样例进入正确的编程二级场景。
- 标题高置信度规则优先于模糊标签。
- 全部 4456 条模板都具有完整的一级功能和二级场景。
- 功能树计数总和等于模板总数。
- 一级、二级、组合筛选和跨一级二级场景筛选正确。
- 现有来源、原始分类、图片相关和关键词筛选保持有效。
- 列表摘要仍不返回完整 Prompt，详情仍返回完整模板。

### 静态前端测试

- 页面包含一级功能、二级场景和高级筛选容器。
- 来源筛选位于默认收起的高级筛选内。
- JavaScript 请求使用 `functionCategory` 和 `functionScene`。
- 清除筛选覆盖全部新旧筛选状态。

### 浏览器验收

- 桌面端默认显示 4456 条总数和一级功能导航。
- 选择“编程与技术开发”后只显示该一级分类，并出现全部编程二级场景。
- 选择“Bug 排查与调试”后列表与计数同步更新。
- 展开高级筛选后仍能按来源继续过滤。
- 移动端两级导航可局部横向滚动，页面无整体横向溢出。
- 浏览器控制台无错误，相关请求均返回成功响应。
